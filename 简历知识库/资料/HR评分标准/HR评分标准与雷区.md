# HR 评审框架与简历风险

> 初次整理：2026-09-02  
> 证据化修订：2026-09-03  
> 定位：用于人工复核和改进优先级，不模拟任何具体公司的真实筛选算法

---

## 一、使用边界

不同公司、ATS、岗位和招聘阶段没有统一的阅读秒数、关键词权重或录用分数。本文不再使用“6 秒决定去留”“关键词占 40%”“90 分必进面试”等无法通用验证的结论。

本框架只能回答：

- 信息是否真实、相关、清晰、可解析。
- 经历是否写明个人动作和结果。
- 简历是否适配目标 JD 和投递渠道。
- 哪些问题应优先修复。

不能回答：

- 某公司一定会不会录用。
- 某 ATS 的真实内部权重。
- 某学历、学校、关键词比例或页数是否必然触发淘汰。

---

## 二、四层评审顺序

### 2.1 第一层：阻断性错误

出现以下问题时，应先修复再讨论文案优化：

- 姓名、电话、邮箱、公司、学校、专业或日期错误。
- 关键事实相互冲突，且未标注待确认。
- PDF 是整页图片、文本无法提取或阅读顺序严重错乱。
- 字体乱码、内容裁切、链接失效、文件损坏。
- 写入无法证明的岗位、职责、技能、证书、奖项、数字或结果。
- 投递文件格式不符合招聘公告要求。

### 2.2 第二层：岗位相关性

检查：

- 求职方向是否明确。
- 最相关的教育、实习、项目或作品是否排在前面。
- JD 中与本人真实经历相符的职责、工具、交付物和行业词是否自然出现。
- 无关内容是否挤占关键证据空间。
- 设计、影视、AIGC、新媒体岗位是否在页首提供作品集文字 URL。

### 2.3 第三层：证据与表达

检查：

- 每条经历是否写清组织、角色、时间、个人动作和结果。
- 团队成果是否与个人贡献分开。
- 有可靠口径的成果是否量化。
- 没有数字时，是否提供上线、交付、验收、采用、获奖、复用或作品完成等可验证结果。
- “主导、独立、统筹、负责”等词是否与事实相符。
- “参与、协助”若真实，是否补充了具体贡献，而不是被错误升级为“主导”。

### 2.4 第四层：版式与扫读

检查：

- 章节名、字体、字号、日期、标点和项目符号是否一致。
- 是否有足够留白和清晰层级。
- ATS 主投版是否优先单栏，或已实测双栏文本顺序。
- 关键信息是否不依赖图标、二维码、页眉、页脚或图片。
- 页数是否符合候选人阶段、岗位和招聘公告；应届生通常优先一页，但不是绝对规则。

## 三、100 分内部质量量表

> 这是知识库内部 QA 工具，不是招聘概率模型。分数用于排序修复项，不对录用结果作保证。

| 维度 | 分值 | 评分依据 |
|---|---:|---|
| 事实与一致性 | 30 | 关键事实可追溯；无冲突、编造或夸大；团队与个人边界清楚 |
| 岗位相关性 | 25 | 章节和内容围绕目标 JD；真实关键词自然出现；重点排序合理 |
| 经历证据力 | 20 | 动作、对象、方法、交付和结果完整；数字有可靠口径 |
| 可读性与版式 | 15 | 层级、留白、字体、日期和标点一致；无裁切和乱码 |
| ATS/文件可用性 | 10 | 文件格式正确；文本可提取；阅读顺序、链接和关键字段可用 |
| 总计 | 100 | 仅用于内部质量比较 |

### 3.1 解释方式

- **85–100**：结构和事实较完整，可进入定向微调与最终渲染检查。
- **70–84**：基本可用，但仍有明显相关性、证据或版式问题。
- **50–69**：需要重组内容或补充证据。
- **0–49**：存在阻断性错误、严重事实风险或文件不可用问题。

即使得分较高，也不代表会获得面试；即使得分较低，也不能用虚构数字或夸大职责提高分数。

## 四、常见风险及修复顺序

| 优先级 | 风险 | 修复方式 |
|---|---|---|
| P0 | 事实错误、造假、隐私泄露、文件损坏 | 立即停止交付，回到原始材料核验 |
| P1 | 日期冲突、公司/学校字段缺失、文本不可提取、严重裁切 | 修复后重新导出并检查 |
| P2 | 目标岗位不清、相关经历排序错误、作品集入口缺失 | 按 JD 重组结构 |
| P3 | bullet 空泛、结果不明确、关键词不足 | 用真实证据改写 |
| P4 | 留白、配色、标点、文件名等细节问题 | 最终润色阶段处理 |

## 五、不同岗位的复核重点

| 岗位类型 | 重点证据 |
|---|---|
| 技术岗 | 项目深度、技术选择、个人实现、验证指标、代码或演示链接 |
| 产品岗 | 问题定义、用户/业务分析、方案、协作、上线与结果 |
| 运营岗 | 内容或活动策略、渠道、用户对象、复盘和真实业务结果 |
| 设计岗 | 个人角色、设计过程、系统性、交付结果、作品集 |
| 影视/AIGC/新媒体 | 剧本/分镜/生成/剪辑/调色/声音中的真实环节、成片和作品集 |
| 销售岗 | 客户对象、销售动作、业绩口径、周期和可核验结果 |
| 金融/咨询 | 项目类型、分析方法、模型/报告交付、行业知识和合规表述 |
| 研究/学术 | 研究问题、方法、贡献、发表/会议/数据和机构要求 |

岗位差异不应被简化为“某类公司一定只看学校”或“所有 bullet 必须有数字”。

## 六、外部 ATS/AI 工具

使用 Jobscan、Resume Worded、Big Interview 或其他在线服务前：

1. 核验官方隐私政策、数据保留、训练用途和删除机制。
2. 明确告知将上传的文件和字段。
3. 对电话、邮箱、地址、证书编号等不必要信息进行脱敏。
4. 获得用户对本次上传的明确授权。
5. 将评分或建议视为辅助信号，不当作录用概率。

优先本地完成：PDF 文本提取、章节检查、链接检查、关键词对照和人工扫读。

## 七、提交前检查清单

### 事实

- [ ] 所有关键事实均有候选人材料或明确确认支持。
- [ ] 所有数字均能解释来源和口径。
- [ ] 没有把知识库范例数据复制到真实简历。
- [ ] 没有把团队成果全部归为个人成果。

### 相关性

- [ ] 目标岗位明确，最相关证据位于前半页。
- [ ] JD 真实匹配词自然出现，没有堆砌。
- [ ] 删除或压缩了低相关内容。

### 文件与版式

- [ ] 格式符合招聘公告。
- [ ] PDF 文本可选择、复制、搜索，提取顺序正确。
- [ ] 无乱码、裁切、换行异常或字体替换。
- [ ] 电话、邮箱、作品集 URL 可读且可点击。
- [ ] 创意展示版与 ATS 主投版事实完全一致。
