# 简历结构范式与 ATS 友好规范

> 初次整理：2026-09-02  
> 本次核验：2026-09-03  
> 适用范围：通用求职简历；具体招聘公告、地区规范和岗位要求优先

---

## 一、结构原则

简历没有适用于所有人的固定章节顺序。通用原则是：**将目标雇主最需要、且候选人证据最充分的信息放在前面**；同一章节通常按时间倒序排列。

### 1.1 应届生 / 早期职业常用结构

1. 基本信息：姓名、电话、邮箱、城市、求职方向。
2. 作品集 / GitHub / 专业主页：仅在岗位相关时加入，使用可点击文字 URL。
3. 教育背景：学校、专业、学历、毕业时间；GPA、课程只在有利且相关时加入。
4. 实习 / 工作经历。
5. 项目 / 课程项目 / 比赛 / 校园经历。
6. 技能。
7. 相关获奖与证书。
8. Summary：可选，只在需要快速解释定位、转行或复合背景时使用。

如果项目比实习更能证明目标岗位能力，可将项目提前。没有相关实习时，课程项目、个人项目、比赛和校园实践可以承担能力证明作用。

### 1.2 资深候选人常用结构

1. 基本信息。
2. 简短职业概述。
3. 核心工作经历和代表成果。
4. 重点项目。
5. 教育背景。
6. 技能、证书或专业资格。

工作经历应占主要篇幅，但不存在适用于所有行业的固定百分比。

## 二、ATS 友好不等于“迎合一个统一算法”

ATS（Applicant Tracking System）用于接收、管理或解析申请材料，不同系统、公司和岗位的解析及筛选方式并不相同。知识库不使用“某比例企业使用 ATS”或“达到某分数即可通过”等未经核验的统一结论。

### 2.1 稳定原则

- 使用清晰、标准、语义明确的章节标题。
- 保证正文是真实文本，而不是整页截图。
- 关键信息不只存在于头像、图标、二维码、页眉或页脚中。
- 日期、标点、字体和项目符号保持一致。
- 经历中写清组织、角色、时间、个人动作和结果。
- 从 JD 提取真实匹配的关键词，自然写入经历、项目和技能。
- 导出后检查文本提取顺序，不能只看视觉效果。

### 2.2 文件与版式

| 项目 | ATS 主投版建议 | 说明 |
|---|---|---|
| 文件格式 | 服从招聘系统要求；允许 PDF 时使用文本型 PDF | 某些系统明确要求 DOC/DOCX，不能一律规定 PDF 优先 |
| 文件名 | `姓名_目标岗位_日期或年份.pdf` | 保持可识别和可版本管理 |
| 字体 | 易读且跨设备稳定；正文通常 10–12 pt | MIT CAPD 的英文简历建议为 10–12 pt |
| 边距 | 通常 0.5–1.0 英寸 | MIT CAPD 明确建议 |
| 表格 | 避免复杂嵌套表格 | 简单表格也必须实测解析顺序 |
| 图标 | 不用图标代替“电话/邮箱/链接”等字段文字 | 图标可装饰，但不能承载唯一信息 |
| 头像 | ATS 主投版默认不放；以地区和单位要求为准 | Harvard 的美国求职指南明确建议不放图片 |
| 页眉页脚 | 不放唯一的关键字段 | 不同解析器处理能力不同 |
| 双栏 | 主投版慎用并实测；展示版可条件使用 | 不是绝对禁止，核心是阅读顺序和投递场景 |

### 2.3 关键词

关键词来源：

1. JD 的岗位职责。
2. 必备技能、工具和证书。
3. 交付物、业务对象和行业术语。
4. 公司官网或同类岗位中反复出现的真实要求。

禁止：

- 写入本人不具备的技能。
- 隐藏关键词或机械堆词。
- 为追求某个评分工具的分数，破坏自然表达。
- 使用统一的“命中率合格线”承诺筛选结果。

## 三、经历条目写法

推荐公式：`具体动作 + 任务/对象 + 方法或工具 + 可验证结果`。

- 结果可以是数字，也可以是上线、交付、采用、验收、获奖、复用、流程改进或作品完成。
- 只有在原始材料或候选人确认支持时才量化。
- “主导、独立、统筹、负责”等词必须准确反映责任边界。
- “参与、协助”并非禁词；当事实确实是协作角色时，应保留并补充具体贡献。

### 3.1 STAR 的简历化使用

- S/T：用少量上下文说明任务和目标。
- A：明确个人采取的动作、方法和工具。
- R：写可验证结果。

简历 bullet 不必机械写全四个标签，应压缩为 1–2 行可扫读内容。

## 四、长度与排版

### 4.1 页数

- 应届生和早期职业候选人：通常优先 1 页。
- 高级学位、研究经历较多、长期从业或岗位明确要求完整记录：可用 2 页或 CV。
- 学术 CV、政府职位和部分国际申请有独立规则，应服从机构说明。

MIT CAPD 建议一般简历保持一页；高级学位或约 10 年以上丰富经验可使用两页。这是常见规范，不是所有场景的“铁律”。

### 4.2 参数

- 正文字号：默认 10–12 pt；高密度视觉展示版不得低于经用户批准的可读下限。
- 页边距：通常 0.5–1.0 英寸。
- 字体：Arial、Calibri、Times New Roman 等属于 MIT 示例；中文应选稳定系统字体并检查替换。
- 行距和段距：以清晰扫读为准，不设适用于所有模板的固定倍数。
- 项目符号、日期格式、标点和标题层级全篇一致。
- 颜色保持高对比，不用颜色作为唯一分类信号。

## 五、主投版与创意展示版

### 5.1 ATS 主投版

- 单栏优先。
- 装饰克制。
- 作品集使用文字 URL。
- 不以技能进度条、图形或二维码代替文本信息。

### 5.2 设计 / 影视 / AIGC / 新媒体展示版

- 可使用双栏、品牌色和更强视觉系统，但要保留清晰阅读路径。
- 简历负责事实结构，作品集负责审美、过程与成片证据。
- 页首同时提供作品集文字 URL；二维码只作补充。
- 建议同时保留 ATS 主投版，不用一个高视觉版本覆盖所有渠道。

详见：`优秀简历模板研究与选型指南.md`。

## 六、常见错误

1. 拼写、语法、日期或联系方式错误。
2. 章节混乱，重要信息难以扫读。
3. 只写职责，不写具体动作或结果。
4. 写入无法验证的数字、技能、岗位、奖项或责任强度。
5. 把团队成果完整归为个人成果。
6. 使用整页图片或把关键信息只放在二维码、图标、页眉页脚中。
7. 为压缩到一页而使用过小字号或极窄边距。
8. 一稿多投，不根据 JD 调整相关性排序。
9. 把第三方 ATS 分数当作招聘结果保证。
10. 未经授权向在线工具上传含个人信息的简历。

## 七、投递前检查

### 7.1 事实与内容

- [ ] 每条公司、学校、日期、技能、项目、奖项和数字均可追溯。
- [ ] 目标岗位所需的真实关键词自然出现。
- [ ] 经历按相关性排序，条目以动作和结果为主。
- [ ] 没有知识库范例数据污染真实简历。

### 7.2 ATS 与文件

- [ ] 文件格式符合招聘系统要求。
- [ ] PDF 文本可选择、复制和搜索。
- [ ] 文本提取顺序与视觉顺序一致。
- [ ] 电话、邮箱和作品集 URL 可读且可点击。
- [ ] 无字体替换、乱码、裁切或溢出。

### 7.3 外部工具与隐私

默认使用本地文本提取和人工核验。若拟使用 Jobscan、Resume Worded、Big Interview 或其他在线服务：

1. 先核验服务方、隐私政策、用途、数据保留和删除机制。
2. 说明将上传哪些字段和文件。
3. 删除不必要的身份证明、电话、邮箱、住址和证书编号。
4. 获得用户对本次上传的明确授权。
5. 将工具输出视为参考，不视为录用保证。
