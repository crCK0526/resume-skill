## 一、项目选型原则

1. **先看用途**：简历生成、ATS 文本检查、JD 匹配、多版本管理不是同一问题。
2. **先看官方来源**：只把官方仓库、官方文档和许可证中的明确陈述作为事实。
3. **不以 Stars 排名决策**：Stars 是动态指标，不代表 ATS 通过率、安全性或维护质量。
4. **隐私优先**：涉及真实简历时，优先本地处理或自托管；托管服务需另查隐私政策。
5. **许可证逐项核验**：不能把不同项目笼统写成“均为 MIT/Apache”。
6. **评分不等于录用**：任何解析器或匹配工具都不能代表雇主实际筛选结果。

### 2.1 Reactive Resume

官方资料确认：

- 官方仓库：`amruthpillai/reactive-resume`。
- MIT License。
- 基础使用无需账号。
- 支持 PDF、JSON、DOCX 导出。
- 支持 Docker 自托管。
- 官方声明默认无 tracking/analytics、无广告，并允许完整数据导出和删除。

注意：

- 不使用“30 秒启动”等营销式时长承诺。
- 自托管涉及数据库和版本迁移，部署前应查看当期文档。
- “完全安全”不能在缺少独立审计时作为绝对结论。

### 2.2 RenderCV

官方资料确认：

- 官方仓库：`rendercv/rendercv`。
- MIT License。
- 使用 YAML 管理结构化简历内容。
- 提供 JSON Schema 和严格验证。
- 可生成 PDF，官方列出 9 个主题。
- 官方明确强调纯文本简历适合版本控制。

推荐用途：

- 建立一个事实源，生成面向不同 JD 的多个版本。
- 用 Git 追踪 bullet、日期和技能变更。
- 在自动化流程中做结构校验和确定性输出。

注意：在线站点上传已有简历前，仍需单独核验隐私政策、处理位置和保留规则。

### 2.3 OpenResume

官方资料确认：

- 官方仓库：`xitanggg/open-resume`。
- 许可证为 GNU AGPL-3.0，不是 MIT。
- 项目方声明：无需注册，数据存储在浏览器本地，可离线继续工作。
- 支持导入已有 PDF、实时预览、生成 PDF 和解析文本。
- 项目方选择单栏版式，并称其面向美国求职市场和 ATS。

注意：

- “适配 Greenhouse/Lever”等属于项目方声明，不是独立兼容性认证。
- 解析器显示的内容可用于排查问题，但不能等同于所有 ATS 的真实结果。
- 修改后以网络服务方式提供给用户时，AGPL-3.0 可能触发向网络用户提供对应源代码的义务。

## 三、候选项目：使用前必须重新核验

以下项目可作为后续研究线索，但本轮未逐项核验仓库身份、许可证、维护状态和当前功能：

- Resume-Matcher
- Awesome-CV
- JSON Resume
- LapisCV
- AltaCV
- moderncv
- sb2nov/resume
- Deedy-Resume
- 各类 Typst CV 模板
- 中文商业简历平台和 AI 简历工具

使用前至少检查：

1. 官方仓库和域名是否互相回链。
2. 最近 release/commit 与 issue 状态。
3. LICENSE 正文及二次分发要求。
4. 是否将简历上传服务器。
5. 是否用于模型训练、日志或分析。
6. 是否支持数据删除和导出。
7. PDF 文本提取顺序是否稳定。

## 四、按需求选择

| 需求 | 推荐方向 | 说明 |
|---|---|---|
| 快速编辑、多模板、非技术用户 | Reactive Resume | 基础使用门槛较低；需要高隐私时考虑自托管 |
| 多岗位版本、严格结构、Git 管理 | RenderCV | 内容与排版分离，适合工程化管理 |
| 检查 PDF 文本解析 | OpenResume + 本地提取复核 | 只把结果当辅助诊断 |
| 中文 A4 可编辑交付 | Word/PPTX 受控模板 + 本地渲染 | 中文字体和 Office 兼容性更易人工核验 |
| 设计/影视/AIGC 岗位 | ATS 主投版 + 创意展示版 + 作品集 | 不依赖一个模板解决所有投递渠道 |

## 五、隐私与安全门禁

- 不把真实简历、证书、身份证件或联系方式上传到任意在线工具，除非用户已经明确授权本次上传。
- 授权前说明：接收服务、具体文件/字段、用途、保留方式和删除能力。
- 能本地完成的文本提取、格式检查和版本比较优先本地执行。
- 不执行知识库中的安装命令；命令仅用于说明项目能力，实际部署应另行做供应链和安全审查。
- 生成结果必须人工检查事实、字体、文本顺序、链接和分页。
